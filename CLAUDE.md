# esp32-clock

Настольные часы-дашборд на ESP32 с OLED 128×64 и RTC DS3231: время по NTP с резервом в DS3231, цифровой и
аналоговый циферблат, погода (MET Norway), переключение касанием, настройки в браузере.

Документы:
- `docs/roadmap.md` — **что сделано и что дальше** (начинать новую сессию с него);
- `docs/idea.md` — исходные требования и список расширений;
- `docs/hardware.md` — оборудование с маркировками; `docs/wiring.md` — подключение;
- `README.md` — для пользователя: управление, экраны, команды монитора, настройка Wi-Fi и веб-страница.

## Стек
- PlatformIO + Arduino framework (espressif32 8.0.0, Arduino-core 3.x), плата `esp32dev`
  (ESP32-WROOM-32, 30 pin, CH340C, порт обычно COM3).
- Версии платформы и библиотек закреплены в `platformio.ini` — менять только осознанно.
- Экран: U8g2, SH1106 1.3" (GME12864-77), полный буфер (`_F_`), рисование в буфер → `sendBuffer()`.
- RTC: RTClib (`RTC_DS3231`). Wi-Fi: WiFiManager. JSON: ArduinoJson 7.
- Разделы флеша: `min_spiffs.csv` (приложение до 1.9 МБ, занято ~80%). При сборке следить за `Flash: ... %`.

## Структура
- `include/config.h` — железо (пины, адреса I2C, драйвер экрана, источник ввода), сеть, таймауты и
  **значения по умолчанию** для пользовательских настроек.
- `src/main.cpp` — только связывает модули: `setup()` инициализирует, `loop()` вызывает их `loop()`,
  собирает `screens::State` и раз в секунду (и сразу после ввода) перерисовывает экран.
- `src/settings/` — `settings::` (NVS `settings`): часовой пояс, место/координаты погоды, автовозврат.
  **Новые пользовательские параметры — через `settings`**, модули читают `settings::get()`, а не константы.
  Циферблат хранит `ui` (`ui::setFace`, NVS `ui/face`).
- `src/display/` — `display` (U8g2), `screen_state.h` (данные кадра), `widgets` (значок Wi-Fi, строка
  статуса, температура, заголовок погоды), `weather_icons` (значки примитивами, любой размер), `modes/`
  (`digital`, `analog`, `weather_modes`, `night_clock`), `screens` (оверлеи: портал Wi-Fi, экран состояния),
  `ui` (что на экране: цикл `kScreens` — часы → погода ×3; циферблат `kFaces`; автовозврат на часы).
  Новый экран = файл в `modes/` + строка в `kScreens`; новый циферблат — строка в `kFaces`.
- `src/weather/` — `weather_client` (MET Norway Locationforecast `compact` по HTTPS, обязательный
  User-Agent `kWeatherUserAgent`; ответ ~37 КБ читается целиком, потом JSON с фильтром; часы/дни считаются
  из временного ряда; запрос в задаче FreeRTOS на ядре 0, результат под мьютексом, `snapshot()` для экранов),
  `weather_codes` (symbol_code → `Condition` → значок/текст), `weather_data.h`.
- `src/input/` — `input` (жесты Click / LongPress) поверх источника `source.h`: `touch_source` (GPIO32)
  или `button_source`; выбор — `INPUT_SOURCE` в `config.h`. Код выше `input` не знает, что за источник.
- `src/clock/` — `rtc_clock` (DS3231), `time_service` (`timekeeping::`: системные часы, SNTP, статус, `setTimezone`).
- `src/net/` — `wifi_conn` (`net::`): WiFiManager, состояния Connecting/Connected/Portal/Offline;
  `web_ui` (`web::`): страница настроек `http://esp32-clock.local/` (WebServer + mDNS), работает только в
  Connected (в портале порт 80 занят WiFiManager).
- `src/diag/` — `i2c_diag` (скан шины, проба проводки `[live]`), `serial_cmd` (команды монитора порта).
- Модули — пространства имён, без глобальных объектов в заголовках.

## Принципы
- Единый источник времени — системные часы ESP32 (`time()` + `localtime_r`, TZ из `settings`).
  DS3231 хранит **UTC**: из него системные часы выставляются при старте (и при долгом отсутствии NTP),
  в него пишется время после каждой NTP-синхронизации. Флаг «синхронизировано хоть раз» — в NVS.
- Ничего не блокирует `loop()`: Wi-Fi/портал неблокирующие, погода — в отдельной задаче, часы идут всегда.
- I2C и экран — только из `loop()` (ядро 1). Фоновая задача погоды их не трогает и не читает `settings`
  (координаты ей передаются копией из `loop()` перед запуском запроса).

## Известные ограничения и подводные камни
- **Ночной режим выключен** (`kNightModeEnabled = false`): на нашем экране любая смена регистров яркости
  (контраст `0x81`, pre-charge `0xD9`, VCOMH `0xDB`) гасит его до отключения питания. Пока режим выключен,
  **не отправлять на экран команд яркости**. Подробности и идеи — `docs/roadmap.md`, этап 6.
- **Open-Meteo** из домашней сети без VPN недоступен (TCP не устанавливается) — не возвращаться к нему
  без проверки. ПК пользователя ходит в интернет через прокси/VPN (`127.0.0.1:10809`), поэтому проверка
  доступности сайтов с ПК не показывает, что видит ESP32.
- **Время в логах монитора** (префикс `HH:MM:SS.mmm >`) — часы Windows, где выставлен другой пояс;
  верное время — в строках прошивки (`[time] ... (MSK-3)`).
- `snprintf` в маленький буфер молча обрезает строку: длинный HTML в `web_ui` добавлять в `String` напрямую.
- Имена функций в inline-обработчиках формы не должны совпадать с `name` полей (`onchange=tz()` при
  `<select name=tz>` вызывал элемент, а не функцию).
- На макетке соединены только 5 точек одного столбца; I2C идёт через столбцы 14 (SDA) и 20 (SCL) — см. `docs/wiring.md`.

## Команды
PlatformIO не в PATH, полный путь: `~/.platformio/penv/Scripts/pio.exe` (далее `pio`).
- Сборка: `pio run`; прошивка: `pio run -t upload` (при `Connecting...` — зажать BOOT);
  монитор: `pio device monitor` (115200, echo и send_on_enter включены); порты: `pio device list`.
- Команды прошивки в мониторе: `help`, `status`, `settings`, `next`, `hold`, `face`, `weather`, `ntp`,
  `touch`, `wifi reset`, `screen test`, `night`/`dim`/`contrast` (ночной режим, ⚠ `contrast` гасит экран).
- Сетевые операции (скачивание пакетов, запросы в интернет) — только вне песочницы.

## Порядок работы
- Каждый этап: Plan mode (сначала вопросы пользователю) → код → **агент сам проверяет компиляцию `pio run`**
  → пользователь прошивает и проверяет на железе → документация (`roadmap.md`, `README.md`, этот файл) →
  предложить сообщение коммита.
- Скачивание новых библиотек (`pio pkg install -e esp32dev`) и прошивку делает пользователь — дать команды
  и попросить лог.
- Git-операции (add/commit/push) делает пользователь — только предлагать сообщение коммита.
- Электрика: модули питаются только от 3.3 В; на DS3231 (стоит CR2032, цепь подзарядки не отключена)
  никогда не подавать 5 В. Питание — USB ESP32 (от ПК или USB-блока); 12 В — только после проверки мультиметром.
- Документация и общение — на русском, комментарии в коде — на английском; надписи на экране и веб-странице —
  на английском.
